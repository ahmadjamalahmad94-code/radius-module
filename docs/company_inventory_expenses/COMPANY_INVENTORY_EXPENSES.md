# مخزون ومصروفات الشركة — Company Inventory & Expenses

> صفحة داخلية للمتابعة التشغيلية فقط. **ليست** جزءًا من دفتر الأستاذ
> الرسمي ولا تؤثر على أي حساب مالي قائم.

## الغرض (Purpose)

دفتر ملاحظات تشغيلي داخلي للشركة لمتابعة:

1. **وارد المخزون** — الأصناف التي تُشترى وتدخل مخزون الشركة
   (كابلات، راوترات، سويتشات، …).
2. **صرف المخزون** — الأصناف التي تُستخدم أو تُصرف من المخزون.
3. **مصروفات الشركة** — المصروفات التشغيلية غير المرتبطة بالمخزون
   (اشتراك إنترنت، أجور عمال، صيانة، حبر طابعة، …).
4. **التقارير** — ملخصات شهرية بسيطة وكميات متبقية وحالة المخزون.

الصفحة موجودة في قسم **المالية** على المسار:

```
/admin/radius/finance/company-inventory-expenses
```

## مبدأ العزل (Isolation principle) — مهم جدًا

هذه الصفحة **معزولة تمامًا** عن المنظومة المالية الرسمية. لا تكتب ولا
تقرأ ولا تعدّل أي شيء في:

- دفتر الأستاذ (accounting ledger / accounting_entries).
- المدفوعات والتحصيلات (payments / payment collection).
- أرصدة العملاء (customer / subscriber balances).
- أرصدة الموزعين (distributor balances).
- مبيعات الكروت والاشتراكات (card sales / subscriptions).
- الإيرادات والأرباح (revenue / profit calculations).
- منطق RADIUS / MikroTik / CoA.

التكاليف (`unit_cost`, `total_cost`, `amount`) **استرشادية فقط**
(informational only). تظهر في ملخصات داخلية ولا تُرحّل إلى أي قيد
مالي. تستخدم الصفحة **جداولها المستقلة الخاصة** بها فقط:

- `company_inventory_items`
- `company_inventory_movements`
- `company_expenses`

## طريقة الحساب (Calculations)

### الكمية المتبقية لكل صنف (Remaining stock)

```
المتبقي = Σ(incoming.quantity)
        + Σ(adjustment.quantity حين تكون موجبة)
        − Σ(usage.quantity)
        + Σ(adjustment.quantity حين تكون سالبة)   ← (تطرح فعليًا)
```

عمليًا في الكود: كل حركة لها `signed_quantity`:

| نوع الحركة | الإشارة |
|------------|---------|
| `incoming`   | + الكمية |
| `usage`      | − الكمية |
| `adjustment` | الكمية كما أُدخلت (قد تكون موجبة أو سالبة) |

`المتبقي = مجموع signed_quantity لكل حركات الصنف`.

### قاعدة منع المخزون السالب (No negative stock)

عند تسجيل **صرف** (`usage`)، يتحقق الـ service أن
`الكمية المطلوبة ≤ المتبقي الحالي`. إن لم تكن متوفرة، تُرفض العملية
مع رسالة عربية واضحة:

> «الكمية المطلوبة غير متوفرة في المخزون. المتبقي الحالي: N <الوحدة>.»

التسوية (`adjustment`) هي الطريقة المقصودة لإدخال تصحيحات يدوية
(جرد، تلف، فاقد) ويمكن أن تكون سالبة، لكنها لا تُنشئ مخزونًا سالبًا
دون قصد لأنها تتطلب إدخالًا صريحًا من الأدمن.

### حالة الصنف (Status badge)

| الحالة | الشرط |
|--------|-------|
| `نفد`     | المتبقي ≤ 0 |
| `منخفض`   | 0 < المتبقي ≤ `low_stock_threshold` (إن وُجد) |
| `متوفر`   | غير ذلك |

### الملخصات الشهرية (Monthly summaries)

- إجمالي قيمة الوارد هذا الشهر = Σ(`total_cost`) للحركات `incoming`
  ضمن نطاق الشهر.
- إجمالي كمية الصرف هذا الشهر = Σ(`quantity`) للحركات `usage`.
- إجمالي مصروفات الشركة هذا الشهر = Σ(`amount`) من `company_expenses`.
- المصروفات حسب الفئة = تجميع `amount` على `category`.

## واجهة المستخدم (UI)

الصفحة عربية RTL بنفس نمط الـ Hub المعتمد (بطاقات ناعمة، حواف
مدوّرة، خلفيات فاتحة). تتكوّن من بطاقات ملخص علوية + أقسام/تبويبات:

1. **ملخص المخزون** — جدول الأصناف مع المتبقي والحالة.
2. **إضافة وارد** — نموذج إدخال وارد جديد.
3. **صرف من المخزون** — نموذج صرف.
4. **مصروفات الشركة** — نموذج + قائمة المصروفات.
5. **السجل والتقارير** — ملخصات شهرية + فلاتر.

## الأمان (Security)

- الصفحة محميّة بالـ login العام للوحة (before_request guard).
- جميع نماذج POST تتضمّن `_csrf_token` حسب نمط المشروع.
- إدخالات الأرقام تُتحقّق من جهة الخادم.
- الحقول النصية تُقصّ/تُنظّف حسب الأعراف القائمة.
- **لا تُعرض** هذه الصفحة في بوابات العملاء أو أي API عام.

## التدقيق (Audit)

تُسجَّل الأحداث التالية عبر خدمة التدقيق القائمة بملخصات عربية:

| الحدث | action |
|-------|--------|
| إنشاء صنف | `company_inventory.item.create` |
| إضافة وارد | `company_inventory.incoming.add` |
| تسجيل صرف | `company_inventory.usage.add` |
| إضافة مصروف | `company_expense.add` |
| تعطيل صنف | `company_inventory.item.deactivate` |

## ملاحظات النشر والترحيل (Deployment / migration)

  تلقائيًا عبر `migrations_runner` بترتيب الاسم (idempotent — يستخدم
  `CREATE TABLE IF NOT EXISTS`).
- لا توجد تبعيات على جداول مالية قائمة؛ الجداول الثلاثة مستقلة.
- لا يلزم أي إعداد بيئة إضافي.
- التراجع (rollback): حذف الجداول الثلاثة لا يؤثر على أي بيانات
  مالية أخرى لأنها معزولة.
