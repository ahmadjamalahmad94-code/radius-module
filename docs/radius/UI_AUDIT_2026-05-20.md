## 🚨 مشاكل حرجة

### CRIT-1: Layout مكسور على forms "wizard" كبيرة

**التأثير**: ثلاث صفحات إنشاء أساسية غير قابلة للاستخدام عمليًا.

**الصفحات المتأثّرة**:
- `/cards/generate` — إنشاء حزمة بطاقات
- `/plans/new` — إضافة عرض/باقة
- `/devices/new` — إضافة جهاز شبكة

**الأعراض المُلاحَظة**:
1. الـ sidebar الأيمن (التنقل) يختفي تمامًا.
2. الـ form يبدأ من منتصف الشاشة (إحداثيات x ≈ 700 بدل x ≈ 280).
3. الـ topbar logo "Hobe Hub" مدفوع لخارج النطاق الافتراضي.
4. Horizontal scrollbar يظهر في الأسفل — يعني محتوى الـ form أعرض من viewport.
5. النصوص labels والـ helper text يتداخلان (overflow).

**النمط المشترك**:
كل صفحة من الثلاث تستخدم **side-nav داخل الـ form** (ToC للأقسام، على يمين الـ form). هذا الـ ToC هو ما يكسر outer layout grid.

**النموذج المضاد** (يعمل):
- `/users/new` و `/users/<u>/edit` — لهما side-nav داخلي أيضًا، لكنهما يعملان. الفرق المحتمل: أقسام أقل عرضًا.

**التشخيص المبدئي**:
الـ form الداخلي يطبق `min-width` كبير (مثلاً `min-width: 1200px`) ينفجر مع الـ outer flex/grid الذي يحوي الـ sidebar الرئيسي. عند التمرير الأفقي يخفي الـ sidebar الأصلي.

**Slice مقترح**: **R10.1** — CSS audit + إصلاح:
- فحص class الـ form-wizard على الثلاث pages.
- إزالة `min-width` الأبدي + استبدالها بـ `max-width: 100%`.
- مراجعة `direction: rtl` interaction مع الـ side-nav الداخلي.

## 🟠 مشاكل بيانات (تعرض أرقامًا غير دقيقة)

### DATA-1: Dashboard "إيراد الشهر" مضلِّل

**الواقع المُلاحَظ**:
- Dashboard card: **إيراد الشهر = 41101.00 JOD**
- `/invoices`: **إجمالي = 0.00 JOD** (0 فواتير)

**السبب**:
في `DashboardService.snapshot()`:
```python
revenue_month=sum((next((p.price for p in plans if p.id == u.plan_id), 0.0)) for u in subs)
```
هذا يجمع `plan.price` لكل subscriber بدل القراءة من جدول الفواتير. النتيجة: رقم وهمي (يضرب 2057 subscriber × price).

**Slice مقترح**: **R10.2a**:
- Replace `revenue_month` و `revenue_today` بـ SQL query على `invoices WHERE status='paid' AND date >= start_of_month`.
- إن لم تكن فواتير → اعرض 0.00 صراحة.
