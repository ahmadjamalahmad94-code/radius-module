# تشغيل المتجر/البوابة على المايكروتيك — الوصل والأعطال

كيف تعمل `store.html` و`login.html` فعليًا بعد رفعهما إلى ملفات الهوت سبوت
على الراوتر، والأعطال المعروفة وحلولها.

## دخول البطاقة (card-login) — منع حلقة إعادة التحميل

- المايكروتيك الافتراضي يستخدم **CHAP**: تُرسل كلمة المرور مهشّمة
  `md5(chap-id + password + chap-challenge)` لا خامًا. التحدّي
  (`$(chap-id)`/`$(chap-challenge)`) يحقنه الراوتر في **login.html فقط**.
- لذلك `store.html` **لا** يرسل الدخول مباشرةً إلى `$(link-login-only)`
  (إرسال PAP خام يفشل تحت CHAP فترتدّ البوابة لصفحة الدخول مرارًا =
  الحلقة). بدلًا من ذلك `hotspotLogin()` يوجّه إلى:
  `login.html?u=<user>&p=<pass>` (الملف بجوار store.html في مجلد الهوت سبوت).
- في login.html يلتقط سكربت الدخول التلقائي **R4** القيمتين `u`/`p`،
  يملأ نموذج الدخول، ويستدعيه بـ`requestSubmit()` فتعمل `doLogin()`
  (CHAP أو PAP حسب الراوتر) ويمنح الراوتر الجلسة فعليًا ثم يوجّه إلى
  `$(link-orig)`. مسار دخول واحد صحيح، بلا ارتداد.

## عنوان الـ API ومفتاح المتجر (cross-origin)

- الصفحة على الراوتر أصلها IP الراوتر؛ تتخاطب مع سيرفر الراديوس عبر
  العنوان المطلق المحقون مكان `{{API_BASE}}` عند النشر (إعداد
  `network.radius_server_ip`، مثل `http://187.77.70.18`).
- كل نداء يحمل ترويسة `X-Store-Key: {{STORE_KEY}}` (مفتاح يُحقن عند النشر).
- نقاط `/api/v1/store/*` تردّ `Access-Control-Allow-Origin: *` وتعالج
  preflight (OPTIONS→204) مع السماح بترويسة `X-Store-Key` — فيعمل النداء
  من أصل الراوتر المجهول مسبقًا.
- **المحتوى المختلط:** صفحة الراوتر تُقدَّم على http؛ نداء https من صفحة
  http مسموح. تجنّب العكس. العنوان يجب أن يكون ضمن
  **walled-garden** قبل تسجيل الدخول وإلا فشل fetch (الصفحة تشخّص ذلك
  بفحص ذاتي ping وتعرض السبب الدقيق).

## الأصول والحجم (قابلية الرفع)

- `store.html` **مكتفية ذاتيًا**: كل الـCSS/JS مضمّن، بلا `<script src>`
  أو `<link>` خارجي، وبلا صور base64 مضمّنة (الشعار برابط `{{TENANT_LOGO_URL}}`).
  خط المراعي من مسار نسبي `fonts/Almarai-*.woff2` بسقوط آمن لخطوط النظام.
- النشر يستخدم `_put_file_smart`: API للصغير، و**FTP المجزّأ** للكبير أو
  كحلّ بديل — فلا نداء `/file/add` ضخم يقطعه الراوتر. عند تجاوز حدّ API
  وغياب FTP **يفشل النشر برسالة واضحة** («فعّل خدمة FTP أو صغّر الشعار»)
  ولا يبتر الملف بصمت. → فعّل خدمة FTP على الراوتر للصفحات الكبيرة.

## زر المتجر في البوابة

- يُحقن **زر متجر ثابت** (HTML خالص بلا اعتماد على JS القالب) في كل
  login.html عند `STORE_ENABLED=yes` — حتى للقوالب ذات الزر الأصلي. إن
  تعطّل سكربت القالب على الراوتر لأي سبب، يبقى هذا الزر الثابت ظاهرًا
  وعاملًا (طريق التسجيل/الشحن إلى store.html).

## معالجة `$(...)` من راوتر أو إس

- الراوتر يستبدل مجموعة متغيّرات ثابتة فقط (`link-login-only`، `chap-id`،
  `chap-challenge`، `error`، `username`، `link-orig`، `mac`…). تُستعمل في
  سياقات HTML آمنة أو كأرقام/hex داخل JS فلا تكسر التحليل.
- JS صفحة المتجر يتجنّب كتابة `'$('` حرفيًا (يفصلها `'$' + '('`) حتى لا
  يلتقطها محلّل الراوتر.

## واتساب الدعم

- رقم `{{SUPPORT_WHATSAPP}}` (أرقام فقط) يُحقن عند النشر؛ يظهر زر «تواصل
  عبر واتساب» البارز في الرئيسية + «تحويل للواتساب» في الشات (`wa.me/<رقم>`).
- إن كان الرقم فارغًا تختفي الأزرار، ويظهر **تلميح للمدير** في لوحة «دعم
  وطلبات المتجر» ليضبطه من «رقم واتساب الدعم» في المصمّم (قسم المتجر).
