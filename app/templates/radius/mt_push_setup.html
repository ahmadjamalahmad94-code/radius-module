لماذا هذا الحلّ؟

عمود «الجهاز / النظام» في فحص البطاقة يحتاج معرفة اسم الجهاز (host-name) ونوع نظام التشغيل (DHCP option 60) لكل MAC. الحلّ الأصلي كان أن يسحب الخادم هذه البيانات من MT API على البورت 8728، لكن لمّا الراوتر خلف NAT أو الفايروول مسكّر، الـ API لا يصل من الخادم.

هذا الحلّ يعكس الاتجاه: نخلّي الراوتر يدفع البيانات إلى الخادم عبر HTTPS كل دقيقتين. الـ outbound HTTPS مفتوح في كل الراوترات تقريبًا (لأنه نفس المنفذ المستخدم للوصول للإنترنت)، فلا يحتاج فتح منافذ خارجية ولا VPN ولا port forwarding.

من أين تجلب الـ Token؟

  1. افتح صفحة إدارة API Tokens (تفتح في تبويب جديد)
  2. اضغط «إنشاء توكن جديد» وسمّيه mikrotik-push (أو أي اسم).
  3. بعد الإنشاء بيظهر الـ token كامل مرة واحدة فقط في بنر أصفر — انسخه فوراً.
  4. ارجع لهذه الصفحة، الصق الـ token في حقل «API Token» تحت.

تنبيه: لأمان النظام نحفظ في قاعدة البيانات hash من الـ token فقط، فالقيمة الأصلية لا تظهر مرة ثانية. لو ضاع منك أنشئ توكن جديد واستبدله في السكربت.

التحقّق + استكشاف الأخطاء

لو ركّبت الـ scheduler بس البيانات ما ظهرت، نفّذ الأوامر التالية على الراوتر للتحقّق: 

# 1) تحقق أن الـ scheduler موجود وفعّال
/system scheduler print where name=hoberadius-push-dhcp

# 2) شغّل المهمة فورًا بدون انتظار 2 دقيقة (للاختبار)
/system scheduler run [find name=hoberadius-push-dhcp]

# 3) شوف آخر سجلات info (الـ /tool fetch بسجّل النتيجة هنا)
/log print where topics~"info" message~"hoberadius"

# 4) شوف الـ errors لو موجودة
/log print where topics~"error" message~"fetch"

# 5) شوف عدد الـ DHCP leases الموجودة
:put [:len [/ip/dhcp-server/lease/find]]

# 6) شوف أول lease كمثال (تأكد أن host-name وclient-id فيهم بيانات)
/ip/dhcp-server/lease/print detail count-only=2

تنبيه شائع: لو الـ URL يبدأ بـ http:// (مش https) فلازم يكون mode=http في الـ fetch — وليس mode=https. السكربت أعلاه يضبط هذا تلقائيًا بناءً على عنوان الخادم.

إزالة الـ scheduler

إذا تريد تعطيل الدفع (مثلاً بعد إصلاح API على الراوتر) نفّذ: 

/system scheduler remove [find name=hoberadius-push-dhcp]
